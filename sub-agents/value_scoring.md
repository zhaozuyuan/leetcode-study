先根据算法本地目录检索文件，详细了解此算法，然后根据以下标准，对算法进行价值打分：

1. 面试高频度与代表性，打分权重 40%。评估在真实技术面试，尤其互联网大厂中的出现频率，以及是否常作为某类问题的代表题被考察。
   - 9-10：Top 级必刷题，几乎所有大厂多次考察，例如 Two Sum、反转链表、LRU Cache。
   - 7-8：常见面试题，出现频率高。
   - 5-6：偶有考察，部分公司出现。
   - 3-4：极少出现于面试。
   - 0-2：几乎不考，纯竞赛或冷门题。

2. 算法核心思想典型性，打分权重 30%。评估题目是否清晰、纯粹地展现经典算法思想，例如动态规划、贪心、分治、回溯、双指针、滑动窗口、二分搜索、前缀和、位运算、图遍历、拓扑排序、并查集等。
   - 9-10：教科书级范例，是该算法思想的代言题，例如 LIS 对于 DP。
   - 7-8：明确需要该思想，虽有少量杂质但非常典型。
   - 5-6：涉及该思想，但非不可替代，或用基础方法也可解。
   - 3-4：只需模拟或简单逻辑。
   - 0-2：无任何算法思想，纯语言练习。

3. 可迁移性与模板价值，打分权重 15%。评估解题思路能否抽象为通用模板或模式，进而解决一系列变体问题。
   - 9-10：可提炼出模板，贯穿一类问题，例如滑动窗口模板、二分边界模板、单调栈模板、回溯模板，覆盖 10+ 同类题。
   - 7-8：提供有用框架，能迁移到若干相似题。
   - 5-6：方法有一定参考性，但变体关联弱。
   - 3-4：特化性强，难以迁移。
   - 0-2：完全孤立。

4. 优化与复杂度分析深度，打分权重 15%。评估是否存在从高复杂度向低复杂度的明显优化路径，是否需要精细的时空复杂度分析、摊还分析或概率期望分析。
   - 9-10：多重优化，例如 O(n^3) 到 O(n^2) 到 O(n log n)，需严密分析均摊、位运算极致优化等。
   - 7-8：有明显优化层次，必须分析并证明复杂度。
   - 5-6：有可优化空间但幅度不大，或常数级优化。
   - 3-4：暴力与最优复杂度相近。
   - 0-2：不考虑优化。
